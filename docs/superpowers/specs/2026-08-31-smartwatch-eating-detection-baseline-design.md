# 智能手表进食检测：可学习迭代基线设计

日期：2026-08-31  
本轮修订：2026-09-01
状态：设计确认版，待用户审阅  
目标截止日期：2026-09-30  

## 1. 目标与边界

本项目的第一目标是做出稳定、可运行、便于学习和迭代的竞赛基线，而不是在第一周追求最大模型或复杂预训练。用户每天可投入约 3–6 小时，因此方案采用“先闭环、再优化”的路线：先完成数据读取、标签、训练、事件输出和竞赛指标，再逐步加入滤波、PPG 融合、方向鲁棒性、时序建模和可选自监督预训练。

本设计不声称穷尽该领域全部研究。外部检索覆盖了直接进食检测、IMU/PPG、多手/方向泛化、下采样、时序卷积、事件级指标、个性化、弱标签、公开数据和公开代码等主要路线。本轮已通过 Context7 查询 PyTorch 和 SciPy 的官方文档，用于核对后续实现的 API、张量形状、损失函数和信号处理边界；Context7 证据只用于工程正确性，不替代领域实验。

竞赛说明 PDF 是本项目的评分和交付约束；本地论文和外部论文只是参考资料，不是必须照搬的模型规定。竞赛核心约束包括：预测进食事件与真实事件的 IoU 大于 0.25 才算正确，计算事件级 Precision、Recall、F1，并报告正确事件的起止时间 MAE；最终还需要 Python 代码、报告、README/可执行运行方式和可复现结果。

### 1.1 总体决策链

后续每个重要选择都必须遵循同一条链条，而不是因为某篇论文使用过就直接照搬：

```text
竞赛/数据事实
  → 可能造成的失败模式
  → 候选方案及代价
  → 选择标准
  → 当前选择
  → 可证伪的验证实验
```

当前已知事实是：目标是事件级 F1 和边界 MAE；标签是时间区间而非细粒度手势；原始数据约 93 GB 且存在异步/缺失传感器流；参与者之间存在个体差异；距离截止日期约一个月，GPU 显存约 8 GB，使用者需要同时学习和迭代。因此方案优先级固定为：

1. 先保证数据和评估闭环正确，否则任何模型分数都没有解释力。
2. 先选择可在单机、短时间内反复运行的模型，避免模型复杂度掩盖数据问题。
3. 每次只改变一个主要因素，并以 participant 分组验证集上的事件 F1、Recall、Precision 和边界 MAE 判断是否保留。
4. 只有当一个改进同时满足“解决明确失败模式、验证集有稳定收益、不会破坏推理和复现”时，才进入最终候选。

这条链条意味着：论文中的方法是提出假设的来源，消融实验才是本项目是否采用该方法的依据。

## 2. 数据与标签设计

### 2.1 原始数据保护

**选择链：**原始数据量大且解析方式尚未完全确认 → 一次性加载和直接改写都会增加内存、时间和不可逆错误风险 → 候选是全量内存处理、复制一份处理、或索引驱动的流式处理 → 在 Windows 单机和 3–6 小时/天的约束下，索引驱动的流式处理成本最低且可回溯 → 因此只读原始数据，用索引和缓存完成处理。

- 不修改约 93 GB 的原始训练数据。
- 原始数据不进入 Git；`.gitignore` 排除数据、缓存、模型权重和输出。
- 通过索引文件定位传感器文件，采用流式读取或分段读取，避免将全天数据一次性加载到内存。
- 内部统一 participant ID、大小写和空格，但保留原始 ID，便于追溯。
- 将数据质量问题写入报告而不是静默删除。

已知需要重点审计的问题包括：时间戳为 0 的缺失流、数据包重复、PPG 通道全零、不同文件的采样率差异、餐段起止时间异常，以及 participant ID 的空格/大小写不一致。

这些审计不是附加工作：如果时间戳、participant ID 或通道有效性错误，后续模型学到的可能是文件格式或个体标识，而不是进食信号。因此第一阶段的验收对象是“数据事实报告”，不是模型分数。

### 2.2 标签

**选择链：**竞赛按连续进食事件计算 IoU，而不是按单个窗口计算准确率 → 训练必须从餐段区间派生窗口标签，推理后还必须恢复连续事件 → 直接把每个窗口独立标为硬 0/1 会放大起止标注误差 → 采用区间标签、边界软标签/忽略区间，并把标签规则配置化 → 用事件级指标验证该标签规则是否真的有利于最终目标。

将餐次的 `beforeTime` 与 `afterTime` 转为时间区间 `[start, end]`。对 `beforeTime > afterTime`、起止相同、缺失值和超出传感器范围的记录生成质量报告，并制定明确处理规则。

第一版采用滑动窗口标签：窗口与进食区间有足够重叠则标记为正样本；起止边界附近保留可配置的软标签或忽略区间，避免把标注误差全部当作模型错误。标签规则必须记录在配置文件中。

### 2.3 数据划分

**选择链：**同一人的相邻窗口高度相关，进食习惯和佩戴方式也具有个体特征 → 随机切窗会让训练集和验证集共享近似片段，得到虚高结果 → participant 分组虽然使分数更低，但更接近隐藏测试泛化 → 因此按 participant 划分，并同时报告个体间波动。

- 训练、验证按 participant 分组，禁止随机切分相邻窗口。
- `test` 目录不参与训练和模型选择；若其中存在本地标签，只用于解析和流程 sanity check。
- 重要实验按 participant 报告均值、标准差和最差个体结果。
- 所有阈值、窗口长度、后处理参数只在训练/验证数据上确定。

## 3. 预处理方案

预处理采用分层实验，不把某种滤波先验硬编码成唯一正确答案。

### P0：可复现的最小预处理

**选择链：**当前尚未确认每种传感器的真实采样率、时间戳语义和数据包重复规则 → 先使用复杂滤波会把解析错误和滤波效果混在一起 → 先做对齐、缺失标记、抗混叠重采样和训练集标准化，可以建立可解释的最小输入 → 因此 P0 不依赖具体论文滤波参数，所有派生通道都有开关。

1. 解析 ACC、GYRO、PPG 的时间戳和数值。
2. 将时间戳为 0 或无效的数据转换为缺失，并产生有效性 mask。
3. 对各传感器流按照真实时间对齐；先通过统计确定原始采样率和数据包结构。
4. 先把异步/不规则数据包还原到统一时间轴，再做重采样；不能把重复的数据包行直接当作等间隔采样点。重采样目标频率做成配置项，首个正式实验用 25 Hz，并对比 15/16 Hz；降采样前使用抗混叠低通。
5. 使用训练集统计量标准化，保存统计量供验证和推理复用。
6. 保留原始标准化通道、加速度模长、陀螺仪模长和有效性 mask。

已有自由生活研究在 16 Hz 下取得了较好的进食/饮水分段结果，因此没有必要默认把所有数据保持在最高频率；但本竞赛传感器结构不同，最终频率必须通过本地验证确定。

25 Hz 只是工程上的首个默认值，不是理论最优值：15/16 Hz 的依据是已有研究，25 Hz 是在保留手腕动作细节和降低计算量之间的折中，50 Hz 是保守高频对照。若 15/16 Hz 在事件 F1 和边界 MAE 上不差于 25 Hz，就选择更低频率；若短动作漏检明显，再保留 25/50 Hz。

### P1：滤波与运动分解消融

**选择链：**原始信号可能包含重力、姿态变化、尖峰和高频动作 → 不处理可能增加学习难度，过度滤波又可能抹掉进食动作和事件边界 → 因此分别检验“去噪”“分离重力”“保留动态动作”三个假设，并保留原始通道作为回退 → 只有事件 F1 提升且边界 MAE 不恶化才采用。

- 加速度低频分量：尝试约 1 Hz 低通，用于重力/姿态信息。
- 动态加速度：原始加速度减去低频分量。
- 陀螺仪低通或轻度平滑。
- 对中值滤波和 5–10 Hz 动态带通单独做实验，不默认启用。
- 原始通道和派生通道同时保留，避免滤波损坏边界后无法恢复。

不同论文在滤波收益上的结论并不一致：一条路线使用五阶中值滤波、低通和带通；另一条路线发现过度平滑会损害动作信息。因此以 P0 作为基线，以验证集事件 F1 和边界 MAE 决定是否启用。

### P2：方向、手腕和佩戴鲁棒性

**选择链：**进食动作在手表坐标系中会随左右手和佩戴旋转改变 → 模型可能把坐标方向误当成类别特征 → 候选是只做训练增强、做轴镜像、或在推理阶段枚举有限方向 → 先从不泄漏测试信息的镜像/增强开始，再用验证集判断方向枚举是否值得增加推理成本 → 因此方向处理是独立消融，不直接写入所有输入。

- 如果测试时提供可信的佩戴手信息，使用 `wear`；不使用只在餐段标签中出现、测试时不可得的 `dietaryHand`。
- 对左右手进行可配置的轴镜像变换。
- 如果佩戴方向未知，测试方向增强和推理阶段的有限方向枚举。
- 把方向处理作为独立消融项，报告其对不同 participant 的影响。

近期工作专门指出固定坐标系会限制跨数据集泛化，并采用方向枚举、左右手变换和加速度/陀螺仪独立分支；其结果仍属于预印本证据，因此只作为强候选方案，不作为保证。

### PPG 处理

**选择链：**PPG 与 IMU 的采样结构、噪声来源和有效性不同，且已有 PPG 论文的目标是宽时间范围的饮食信息而非精确起止事件 → 直接把 PPG 当作普通 IMU 通道或套用外部权重都可能产生域错配 → 因此先保留原始/去趋势/质量信息，交由独立分支学习；PPG 是否有效由消融实验决定。

PPG 采用保守策略：标准化原始波形、去趋势版本、轻度滤波版本和质量 mask 并存。对全零、平坦、异常幅值和缺失包显式编码。PPG 不直接套用饮食内容预测论文的预训练权重，因为其标签是餐食/饱腹感等宽时间范围目标，不是本竞赛的精确事件边界。

## 4. 模型阶梯

### M0：IMU 小型 1D CNN

**选择链：**需要先确认数据和标签能否让模型学到信号 → 直接使用 Transformer、复杂多分支或大规模预训练会增加显存、依赖和调参变量 → 小型 1D CNN 能表达局部时序模式，训练快，失败时容易定位 → 因此 M0 是首个竞赛候选，也是后续改进的唯一对照基线。

- 输入：6 轴 IMU、模长、mask。
- 结构：3–4 个一维卷积块、归一化、激活、池化和二分类头。
- 输出：每个滑动窗口的进食概率。
- 目标：快速确认数据、标签、训练和指标全链路有效。

### M1：IMU + PPG 特征级融合

**选择链：**数据级拼接实现简单但要求两种模态已经正确对齐，并且会让高维/噪声通道直接互相干扰；完全独立到决策级又无法学习“运动与生理信号共同出现”的关系 → 独立 encoder 可以先按模态处理差异，再在特征层交互 → 因此以特征级融合为主，以数据级和决策级作为对照/故障回退。

使用 IMU encoder 和 PPG encoder 两个分支，在中间特征层进行拼接或门控融合，再接一个分类头。这是主推荐模型，比一开始直接拼接所有原始通道更容易处理不同采样率、不同噪声和缺失模态。

训练时随机丢弃 PPG 或 IMU，并输入 modality mask，使模型在某一路信号质量差时不至于完全失效。

门控融合的选择依据是“模态质量随时间变化”：如果 PPG 平坦或 IMU 缺失，模型应降低该分支权重。若门控在小样本上不稳定，则退回普通特征拼接，不能为了结构复杂而保留无收益模块。

### M2：窗口概率的长上下文修正器

**选择链：**局部窗口模型只能看到短时间片段，容易把一次短暂的非进食手腕动作误报成进食；已有全日分析工作显示，利用同一天的概率序列和低频上下文可以减少瞬时误报 → 直接把原始全天信号输入大型模型会增加内存、标签和调参成本 → 先把 M1 的窗口概率按较低频率组成序列，再使用轻量 1D 时序模型或规则化上下文修正 → 因此这是比大模型更低风险的长上下文候选，但必须验证不会把真实短零食过滤掉。

- 输入优先是 M1 的窗口概率、有效性和时间间隔特征，不是未经验证的全天原始信号。
- 只在 M1 已经能检出大部分正事件、主要问题变成短暂误报时启动。
- 最短事件和合并间隔参数必须在 participant 分组验证集上选择。

### M3：局部时序模型

**选择链：**M0/M1 只看固定窗口，可能无法利用前后文来判断一次进食事件是否连续 → TCN/MS-TCN 能用扩张卷积扩大局部上下文，参数和显存通常比 Transformer 更可控 → 但如果基础数据闭环尚未可靠，时序模型只会放大错误 → 因此 M3 只有在 M1 的错误分析明确显示“局部上下文不足或边界不稳”时才启动。

当 M1 已经稳定后，尝试轻量 TCN 或 MS-TCN，扩大局部时序上下文，改善连续事件和边界。MS-TCN 的思想适合参考，但官方仓库依赖较老的 Python/PyTorch 版本，不直接复制整个工程。若错误主要是整段日级误报，优先 M2；若错误主要是窗口边界和局部连续性，优先 M3。

### M4：可选自监督预训练

**选择链：**本地有大量传感器数据，但餐段标签有限 → 自监督学习可能改善跨人的表示；然而预训练本身会消耗实现和验证时间，也可能学到设备/个体差异 → 先用监督 M0/M1 建立收益基线，再做一次小规模、可回退的预训练实验 → 只有微调后 participant 分组事件 F1 稳定提升才保留。

优先利用本竞赛未标注的训练传感器数据做轻量 masked reconstruction 或对比学习，再微调进食检测。外部数据预训练只有在传感器单位、采样率和通道语义足够一致时才尝试。自监督预训练是加分项，不得阻塞 M0/M1。

## 5. 训练策略

**选择链：**进食窗口通常远少于非进食窗口 → 全部使用普通二分类损失会让“全部预测为非进食”成为低成本解 → 一开始直接使用 focal loss 或复杂重采样又会引入额外超参数和样本分布变化 → 因此 M0 采用训练集统计的 `pos_weight` 加权 BCE，保持样本时间分布相对稳定；若验证集仍明显漏检，再单独测试 focal loss 或 participant-aware 正样本采样。

- 批次和采样不跨 participant；不把相邻正窗口无限复制。
- 训练增强优先使用小幅噪声、幅值缩放、时间遮挡和合法的轴变换；增强后标签区间必须仍然成立。
- 以事件级 F1 为主监控指标，以 Precision、Recall 和 start/end MAE 解释变化；不以窗口 accuracy 作为早停依据。
- 保存随机种子、训练/验证 participant 列表、归一化统计量和完整配置。
- 训练失败先检查输入、标签和采样，再调整模型；禁止用加深网络掩盖数据错误。

硬负样本挖掘放在基线之后：先用 M0/M1 找出验证集或训练集中的稳定误报，再把这些非进食窗口提高采样权重。如果模型连基础正样本都识别不了，硬负样本没有意义。

## 6. 事件解码与评估

**选择链：**模型输出的是窗口概率，而竞赛评价的是连续事件 → 直接按每个正窗口提交会产生碎片、重复事件和错误边界 → 需要一个独立、可解释、可调参的事件解码器 → 因此所有模型共用同一套解码和评估，防止模型改进与后处理改进混在一起。

窗口概率不能直接作为最终答案。统一经过事件解码器：

1. 由验证集确定窗口概率阈值。
2. 可选高阈值开始、低阈值结束的 hysteresis。
3. 合并相邻或间隔很短的正片段。
4. 删除明显过短的片段。
5. 将窗口时间映射回连续事件区间。
6. 用竞赛 IoU > 0.25 计算事件 Precision、Recall、F1。
7. 对正确匹配事件计算 start/end MAE。

HMM、DBSCAN 和更复杂的时序平滑只作为后续实验；其间隔和最短时长参数不能直接照搬其他数据集。若简单阈值已经达到稳定结果，复杂解码器必须同时满足 F1 提升、边界 MAE 不恶化和跨 participant 结果不更不稳定。

## 7. 选择标准与候选淘汰规则

为了让每个方案都有可检查的结论，所有实验使用以下固定决策规则：

| 决策项 | 候选 | 选择逻辑 |
|---|---|---|
| 采样率 | 15/16、25、50 Hz | 先满足有效时间对齐；以事件 F1 为主，边界 MAE 为辅；分数接近时选计算量更低者 |
| 窗口 | 15 s/3 s、10 s/5 s 等 | 15 s/3 s 作为已有研究支持的首个候选；若短事件漏检或边界偏差明显，再比较更短窗口 |
| 滤波 | 无滤波、中值、低通/动态分量 | 只有在事件 F1 提升且 MAE 不恶化时保留；原始通道始终可回退 |
| 方向处理 | 无、训练增强、推理枚举 | 只有当跨 participant 的方向敏感性和验证收益明确时增加推理成本 |
| 融合 | 数据级、特征级、决策级 | 先用数据级建立对照，再用独立 encoder 测特征交互，最后用决策级做缺失模态回退 |
| 模型 | 小 CNN、概率序列修正器、TCN/MS-TCN、Transformer | 只有当前一级模型的错误分析说明上下文不足时升级；优先选择显存和依赖风险更低的模型 |
| 预训练 | 无、内部自监督、外部预训练 | 必须在相同 participant 划分上稳定提升；否则不纳入最终模型 |
| 后处理 | 阈值/合并、hysteresis、HMM/DBSCAN | 先用最简单可解释的解码器；复杂方法必须证明跨人稳定收益 |

候选模型的最终排序为：第一看事件 F1；若 F1 差异小于 0.01，则依次看 participant 间标准差、起止时间 MAE、模型和依赖复杂度。这样既不把“简单”凌驾于分数之上，也避免为了极小的验证集波动引入不可复现的复杂结构。

## 8. 实验顺序

实验顺序遵循“先验证前提，再增加自由度”的依赖关系：先验证解析/采样率/标签，再验证单模态表示，然后才加入滤波、方向、PPG 和高级时序结构。如果前一个实验没有稳定闭环，后一个实验没有可解释的输入基础，不启动。

每次只改变一个主要因素，并保存配置、随机种子、participant 划分和结果。

```text
E0  IMU + 1D CNN + P0
E1  加入模长与质量 mask
E2  15/16/25/50 Hz 对比
E3  滤波与动态分量
E4  左右手镜像与方向处理
E5  IMU + PPG 数据级融合
E6  IMU + PPG 特征级门控融合
E7  modality dropout 与硬负样本挖掘
E8  事件后处理、软边界与阈值优化
E9  窗口概率的长上下文修正器
E10 TCN/MS-TCN 或一次轻量自监督预训练
```

预期最先带来收益的不是大模型，而是正确的数据对齐、按人划分、质量 mask、硬负样本和事件后处理；如果实验结果不支持这一判断，以验证结果为准。

## 9. 公开研究和代码的使用边界

- [Wang et al., 2026](https://arxiv.org/html/2607.01376v1)：参考方向不变性、独立模态分支、跨模态注意力和事件后处理；由于是预印本且数据集不同，只做候选设计参考。
- [Wageningen/IEEE BSN 2023](https://edepot.wur.nl/651044)：参考双手数据、下采样和 MS-TCN 思路。
- [Kyritsis et al., 2020](https://arxiv.org/abs/2010.07051)：参考 gesture/bite 到 meal episode 的两阶段路线。
- [Bahador et al., 2021](https://mhealth.jmir.org/2021/1/e21926/)：参考多模态表示和缺失数据影响，但其二维协方差/轮廓表示暂不作为基线。
- [Top-Down Detection of Eating Episodes](https://pmc.ncbi.nlm.nih.gov/articles/PMC8869422/)：支持用较长上下文减少短窗口误报，但其长窗口和数据集不能直接替换当前基线。
- [Daily Pattern Analysis](https://pmc.ncbi.nlm.nih.gov/articles/PMC10904729/)：支持在局部窗口概率之后增加日级上下文修正器；该模块作为 M2 后置实验。
- [Eating Speed Measurement](https://arxiv.org/html/2401.05376)：支持 gesture→episode、TCN-MHA 和对方向/双手/零食误差的分析，但其细粒度标签不等于本竞赛标签。
- [Robust IMU+Radar Multimodal Learning](https://arxiv.org/abs/2507.07261)：支持缺失模态训练和跨模态注意力的机制假设；雷达不是本竞赛传感器，所以只迁移鲁棒性思想。
- [WIMID Dataset](https://zenodo.org/records/18176217)：提供 100 Hz 实际频率变化、插值和中值滤波的公开数据例子，支持我们先恢复时间轴再评估滤波。
- [Commercial Smartwatch Eating Detection](https://journals.plos.org/digitalhealth/article?id=10.1371/journal.pdig.0001539)：支持严格未见个体评估和个体差异风险；不把个性化校准作为默认方案。
- [MS-TCN 官方仓库](https://github.com/yabufarha/ms-tcn)：参考时序卷积结构，不直接使用旧环境。
- [ArWISE](https://github.com/WSU-CASAS/ArWISE)：参考可穿戴信号的 1D CNN、对比学习和 masked autoencoder。
- [CuisineSense](https://github.com/joeeeeyin/CuisineSense)：参考 IMU 进食状态代码组织，但其任务和数据不同，先检查许可证再考虑复用。
- [EatingDetectionIJS](https://github.com/simon2706/EatingDetectionIJS)：参考数据和任务描述，不假设其中包含可直接运行的完整竞赛训练代码。

## 10. 证据链与设计映射

### 10.1 证据等级

- **A 级：**与腕部进食检测、连续事件或相同事件级指标直接相关的正式论文/官方数据。
- **B 级：**相邻任务、不同传感器或预印本，但能支持某个具体机制假设。
- **C 级：**PyTorch/SciPy 官方文档，只证明工程 API 和数值行为，不证明模型在本竞赛上有效。
- **D 级：**本地数据审计和竞赛规则，只对本项目数据有效。

证据链的结论不是“论文用了 X，所以我们必须用 X”，而是“论文观察到 Y，因此提出假设 X；在本项目验证集上检验 Z，只有通过才采用”。

### 10.2 研究证据到方案的映射

| 等级 | 证据事实 | 对本项目的推理 | 设计决定 | 验证方式 |
|---|---|---|---|---|
| D | 竞赛按连续事件 IoU > 0.25、F1 和起止时间 MAE 评分 | 窗口 accuracy 不能代表最终成绩 | 从第一版实现事件解码和 MAE | 用人工构造区间测试 IoU、空预测和边界匹配 |
| D | 本地传感器文件存在异步时间戳、0 时间戳、重复包和全零 PPG 通道 | 若先训练，模型可能学到解析错误 | 先做时间轴/质量审计，缺失用 mask | 小样本报告每条流的采样间隔、缺失率和重复率 |
| A | 进食检测研究采用严格跨人验证，发现个体差异会显著影响结果 | 随机切窗会高估隐藏测试表现 | participant 分组训练/验证 | 检查任何 participant 不出现在多个划分 |
| A | 公开全日研究发现短窗口容易产生瞬时误报，日级概率上下文可改善餐段检测 | M1 若主要误报而不是漏检，需要长上下文 | 加入 M2 概率序列修正器，而非直接输入全天原始信号 | 比较 M1 与 M2 的 FP/TP、F1 和短零食 Recall |
| A | 长窗口 CNN 和局部 gesture→episode 两条路线都能利用餐段上下文，但标签粒度和边界要求不同 | 当前只有餐段区间标签，直接做 bite 监督不成立 | 先做窗口→事件；gesture→episode 作为后续路线 | 对比窗口模型与序列模型的事件边界 MAE |
| A/B | 双手研究和跨数据集研究都显示，佩戴手/坐标方向会造成漏检或泛化下降 | 6 轴原始坐标可能把佩戴姿态当成类别 | 镜像、方向增强和有限方向枚举做消融 | 按佩戴手/方向分组报告 F1 和 Recall |
| A/B | 研究使用下采样和中值滤波，但不同数据集对平滑收益并不一致 | 采样率和滤波参数不能直接照搬 | P0 原始+mask，P1 滤波消融；目标频率可配置 | 15/16、25、50 Hz 以及滤波开关的同划分对照 |
| B | IMU+雷达的研究在缺失模态时仍受益于鲁棒多模态训练 | 虽不是 PPG，但“模态会缺失”这一机制与本数据相同 | modality dropout、质量 mask 和决策级回退 | 人为屏蔽 PPG/IMU，观察性能下降是否变小 |
| B | PPG/IMU 相关研究更多关注餐食内容、生理响应或个性化，而非精确事件边界 | PPG 可能补充信息，但不能预设其能定位边界 | PPG 独立 encoder，保守滤波，不使用不匹配的外部权重 | IMU-only、PPG-only、数据级、特征级、决策级五组对照 |
| A/B | 研究报告手吃、零食、不同环境和不同方向更难检测 | 平均 F1 可能掩盖关键失败类型 | 错误分析按餐段时长、手部/用具、时间段和 participant 分层 | 保存每个事件的 TP/FP/FN 与边界误差 |
| B | WIMID 等公开数据将 100 Hz 的实际频率变化先插值并进行中值平滑 | “名义采样率”不等于真实等间隔采样 | 先恢复统一时间轴，再决定是否降采样/滤波 | 输出真实间隔分布和重采样前后长度 |
| B | 商业手表研究在未见个体上的性能明显低于个体内结果，并提出校准与额外传感器作为方向 | 个性化结果不能直接当作竞赛泛化结果 | 默认不做用户校准；只有测试协议允许才研究 | 只用未见 participant 的验证结果做主表 |

### 10.3 Context7 工程证据到实现的映射

| 官方文档事实 | 工程结论 | 对设计的影响 |
|---|---|---|
| [PyTorch `Conv1d`](https://github.com/pytorch/pytorch/blob/main/torch/nn/modules/conv.py) 接收 `(N, C, L)`，并支持 padding、stride、dilation | 时序通道应明确放在 `C` 维；TCN 可由 dilation 扩大感受野 | M0 使用统一的 `(batch, channels, time)` 接口，M3 再增加 dilation |
| [PyTorch `BCEWithLogitsLoss`](https://github.com/pytorch/pytorch/blob/main/torch/nn/modules/loss.py) 将 sigmoid 与 BCE 合并，并用数值稳定形式；`pos_weight > 1` 会偏向 Recall | 不应在 loss 前手动 sigmoid；类别不均衡可先用训练集负/正比例构造 `pos_weight` | M0 选择加权 BCE，阈值仍需在验证集调，不能把 loss 权重当作最终阈值 |
| [SciPy `resample_poly`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.resample_poly.html) 将多相滤波用于重采样；滤波器应先抑制降采样混叠 | 不规则包不能直接重采样；先统一时间轴，再用抗混叠重采样 | P0 明确区分“时间轴恢复”和“目标频率转换” |
| SciPy 的[中值滤波](https://github.com/scipy/scipy/blob/main/signal/_signaltools.py)适合抑制尖峰，[`sosfiltfilt`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.sosfiltfilt.html)可做零相位滤波但涉及边界填充 | 中值滤波和零相位滤波都是有副作用的离线处理 | P1 只做消融，记录边界策略，不能默认替换原始信号 |

这些 Context7 证据只支持“代码怎样正确实现”，不支持“该方法一定提升本竞赛 F1”；后者仍由本项目实验决定。

## 11. 时间安排与验收标准

**选择链：**距离 9 月 30 日约一个月、每天投入 3–6 小时 → 如果把预处理、基线和高级研究串到最后才集成，任何一个环节失败都会没有可提交版本 → 因此前半段必须完成可提交的 M0/M1，后半段只做可回退的增量实验，并预留打包和报告时间 → 高级方向最多选择一个，不能同时启动 TCN、复杂注意力和自监督。

- 9 月 1–3 日：环境、数据审计、采样率和文件解析。
- 9 月 4–7 日：标签生成、事件指标和样本可视化。
- 9 月 8–12 日：完成 M0。
- 9 月 13–16 日：完成重采样、质量 mask、滤波和方向消融。
- 9 月 17–20 日：完成 PPG 数据级/特征级融合。
- 9 月 21–24 日：硬负样本、边界处理和后处理。
- 9 月 25–27 日：只选择一个高级方向：TCN/MS-TCN 或轻量自监督。
- 9 月 28–29 日：固定最终模型、打包运行流程和报告。
- 9 月 30 日：提交。

基线通过标准：在小规模数据上能够稳定完成“读取 → 对齐 → 标签 → 训练 → 验证 → 连续事件输出 → IoU/F1/MAE 计算”；在完整训练数据上能按 participant 重跑；代码不依赖绝对路径；原始数据不被修改；README 能让另一台 Windows 机器按步骤运行。

## 12. 主要风险与应对

| 风险 | 应对 |
|---|---|
| 数据包结构或采样率理解错误 | 先做采样率、时间戳、重复包和通道有效性报告 |
| 随机切窗造成泄漏 | 全流程使用 participant 分组 |
| 滤波损坏动作边界 | P0 保留原始通道，滤波只做消融 |
| PPG 缺失或噪声大 | quality mask、modality dropout、独立 PPG 分支 |
| 窗口 F1 好但事件 F1 差 | 从第一版实现 IoU 事件解码和边界 MAE |
| 高级模型耗时阻塞提交 | M0/M1 先冻结为可提交候选 |
| 外部代码依赖过旧或许可证不明 | 只提取思想；复制前检查许可证和依赖 |

## 13. 工程与环境决策

**选择链：**用户需要在 Windows 上学习、重复实验并最终提交可复现代码 → 修改 Anaconda base、写死绝对路径或把数据和代码混在一起都会降低可复现性 → 因此使用独立 Conda 环境、配置驱动的相对路径和模块化目录；环境版本以本机 RTX 5060 与官方 PyTorch CUDA 支持为依据，在安装时验证，不凭记忆写死。

- Git 根目录固定为 `E:\bme_compitition`，便于竞赛代码、报告和实验记录统一管理。
- 原始数据留在官方目录，代码只通过配置读取；生成的缓存、权重和结果放在被忽略的目录。
- 后续实现至少分为数据读取/对齐、标签、特征、模型、训练、事件评估和命令行入口，避免一个脚本同时承担所有职责。
- 最低测试集合包括：时间戳为 0 的处理、participant 分组无交叉、窗口标签边界、IoU 事件匹配、空预测/空真值，以及一小批数据的训练 smoke test。
- 环境安装完成后先运行 GPU 可见性和一个极小 PyTorch 训练测试，再开始读取完整数据；这样可以把环境故障与数据/模型故障分开。
