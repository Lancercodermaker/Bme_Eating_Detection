## 1. Authority and scope

The [2026-09-22 A2 design draft](../superpowers/specs/2026-09-22-a2-context-verifier-redesign.md) proposed a fixed-candidate, 26-dimensional context verifier. Its `NOT_EXECUTION_AUTHORIZED` status described the state when it was written. On 2026-09-23 the project owner authorized a **separate-conversation validation after thorough design review and an execution document**. This decision supplies the corrections and bounds for that authorization. Where the draft and this decision differ, this decision controls A2 validation. Neither document changes the [A1 result and closure](2026-09-22-a1-end-to-end-feasibility-result.md), the [Formal G1 stop](2026-09-19-formal-g1-local-experimentation-stop.md), or the 2026-09-14 frozen architecture.

Only one fixed `a2_event_context_v1` development validation is authorized, subject to all readiness gates below: reuse the A1 run `artifacts/a1-end-to-end-feasibility-v1-005` candidate roles and scores; preserve its 41 participants, 234 evaluation GT, 5/4/4 nested roles, 4,183 outer candidates, candidate intervals and labels, A1 decoder/evaluator, HGB verifier parameters, seed and inner-selected threshold set `{0.10, 0.25, 0.50}`. Candidate model fit **and candidate model predict** budgets are zero; verifier fit-attempt budget is 25. The later validation may call the new verifier's scoring method only on the legal held-out inner and outer candidate roles in that nested graph. Read only approved derived caches and A1 artifacts. Do not read or stat raw sensor paths; do not access official test or external datasets; do not modify A1 inputs, production, or the canonical GT. The present conversation writes documents only and does not start the validation.

This is a limited research exception to the G1 prerequisite for verifier work, not a Formal G1 pass or authorization for M5/G4, full training, or production. A2 outputs are development evidence because all 41 eligible participants have already informed design decisions. The fixed 75 long false positives without any recorded annotation overlap remain behaviorally unadjudicated; no model score or IMU shape is independent behavior truth.

The teammate's open report is background only: its F1 of 0.6514 uses 153 GT under a different evaluation contract and its context representation is not this fixed 26D A2 schema. It is neither an A2 control nor an A2 input; no report code or data enter this validation.

| P0 | Candidate score NPZ `ids` are integer positions in the 632,100-row `window-identity.json` global order, not stable window IDs or record-local row indices (`a1/execution.py`). | For each of 105 candidate roles, require ordered NPZ `ids` to equal exactly the approved global positions of **all** windows belonging to that role's scored participants; check integer type, range, uniqueness, finite `raw` and `relative`, score provenance and `relative == raw - role_threshold`. Map positions to stable IDs only after this check. Missing scores are `INVALID`, never an empty-context value. |
| P0 | `event-candidates.jsonl` contains GT-derived `label` for training/inner roles; A1 `A1Candidate` enforces 16D. | Project candidate identity/interval/16D/support into a label-free feature input; keep labels in a separate role-scoped training/evaluation join. | P1 | §3 calls 103 FP with no eligible-GT overlap “pure background”; 75 long FP have no overlap with any of 281 recorded annotations but actual behavior is unknown. | Say “FP under the approved annotation contract with no recorded GT overlap.” Do not equate their suppression with proof of detecting true non-eating. ## 3. Frozen A2 input and feature contract

Pin A1 `final-checksums.json` itself to SHA-256 `0543791e90df9e1bcf93111dc45e80678089898409e6888b90584fd18c469025`, then verify every listed file (282 entries), including all score files. Verify each of the 45 A1 code paths registered in `run-manifest.json` against its registered hash; newly created A2 paths are separately frozen and must not be mistaken for A1 code drift. Verify the approved eligibility file and denominator hashes, role graph, score/model provenance signatures, and approved cache manifest/file hashes before any A2 fit. Do not deserialize A1 model pickle files. Approved cache numeric time/coverage arrays and score NPZ can be read with `allow_pickle=False`; no raw sensor path is opened or stated.

Read-only review checked all 105 candidate score roles (10,745,700 scored rows) against the expected ordered global window positions with no missing or reordered IDs. Approved cache geometry for 1,127 records and 632,100 windows reconstructed 2,440 observed-support components; all 72,112 saved candidate rows aligned with their role/participant/record/session/component. Among 66,819 candidates with a same-component post-midpoint window, none had a selected post window ending beyond `candidate.end_ms + 300000`. These are source-feasibility checks, not a model run or a substitute for the later frozen, hash-bound `AUDIT_READY` audit.

For each candidate role, rebuild observed-window-support components from **all** its scored windows grouped by `(participant_id, record_id, session_id)`, not just selected candidate support. Match candidate component IDs and support identities to that role's reconstructed components. `source_segment_id` remains null: the component is not a physical source segment. Hold constant outer candidate counts `[946, 892, 929, 653, 763]` and covered-GT counts `[46, 48, 47, 31, 41]` (total 4,183/213); these are input invariants, not new optimization targets.

The 26D vector consists of the saved 16 A1 features in original order plus the ten features of A2 draft §5 in its published order. Use the saved role-specific `relative` score array after verifying it equals `raw - threshold`. Region membership uses `floor((start_ms+end_ms)/2)` and half-open `inside=[s,e)`, `pre=[s-300000,s)`, `post=[e,e+300000)`, restricted to the same reconstructed component. Empty pre/post have mean/fraction/observed-fraction zero. Inside empty is `INVALID`. Observed fraction uses the draft's frozen divisor 40. The positive-run rule above is binding. No feature, context width, threshold, duration, fusion, seed, class weight or model-family sweep is authorized.

## 4. Execution and interpretation gates

The [A2 execution plan](../superpowers/plans/2026-09-23-a2-context-verifier-validation-implementation.md) is the only execution handoff. Before a real fit it must produce passing synthetic tests, a frozen A2 config/code/input-hash manifest, and a no-fit `AUDIT_READY` audit showing role/score/cache/candidate identities, ordered feature/label digests, 26D finite features, G3 feasibility, resource monitor readiness and complete participant isolation. The run must verify these digests against its actual inputs before fitting. An identity, hash or authorization failure stops as `INVALID`; a resource limit or unavailable measurement stops as `INCOMPLETE_RESOURCE`. Such states are not performance failures. A successful full run is evaluated **once** on the five outer folds. An outcome below the full stage minimum closes this specific 26D variant; no local repair by changing features, thresholds, duration, fusion or seed. A pass is development support only and does not change Formal G1 or grant independent confirmation.
