# 智能手表进食检测：高事件级 F1 架构设计

日期：2026-09-10  
工作区：`E:\bme_compitition\bme_compitition_next`  
目标：从第一天开始优化官方定义的事件级 F1，而不是先优化一个容易训练的窗口级准确率。

## 1. 已确认的工程事实

- 官方判定是事件 IoU 严格大于 0.25 后计算 Precision、Recall、F1，起止时间误差是辅助指标。
- 原始 TSV 并不是“每行一个等间隔采样点”：IMU 和 PPG 都有大量重复时间戳、零时间戳和模态不同步。
- 上一版 1D CNN 的主要失败不是“卷积永远不适合”，而是局部窗口独立打分后依靠阈值和合并规则，产生了分钟级长连续 FP；在这个数据集上，错误的时间轴和稀疏覆盖会把训练/验证信号进一步破坏。
- 两位队友的有效证据都指向“密集覆盖 + 事件级后处理/复核”：TCN 更适合作为长上下文或候选特征，LightGBM/HistGradientBoosting 适合作为强可解释的第一版事件复核器。

因此本版选择“全覆盖候选层 + 事件级复核”的主路线，并保留长上下文 TCN 作为候选打分器和后续可替换模块。

## 2. 系统分层

```text
只读原始 TSV
    -> 时间轴重建/去重/模态质量掩码
    -> 训练 participant 的餐段标签与 dense windows
    -> 高召回候选层（240 s 窗口，15 s 步长）
    -> 事件级复核（局部特征 + 前后上下文 + 可选 TCN score）
    -> 受约束 eventizer（阈值、持续时间、相邻候选融合）
    -> 官方 IoU>0.25 一对一匹配
    -> participant-frozen 验证报告
```

### 时间轴与窗口契约

1. 先按 ACC/GYRO/PPG 的非零时间戳分流并聚合同一时间戳的重复 packet。
2. 主检测轴先使用 IMU 的规则 10 Hz 网格；缺口不插值跨越，缺口两侧不能形成同一个窗口。
3. PPG 保留为独立低频模态和质量掩码，第一轮不允许它改变 IMU 主轴的时间语义。
4. 候选窗口长度为 240 s、步长为 15 s，覆盖率阈值默认 0.8；15 s 局部块可作为候选特征序列，但不能替代 dense grid。

### 候选层

候选层目标是高 Recall，不直接承担最终事件 F1。当前保留两种可比较时间尺度：240 s coarse context 用于长上下文候选，15 s 窗口/7.5 s 步长用于局部运动候选。两者都使用同一时间轴、质量掩码和 participant split；最终事件由复核器决定。队友结果使 15 s local-tree 成为高优先级比较对象，但上一版 1D CNN 失败意味着不能把 local window 直接等同于 local CNN。

如果候选层 Recall 在冻结验证集达不到 0.90，不能进入复杂模型比较。候选层不得跨越时间缺口，不得只给 GT 附近窗口打分。候选概率若在小 split 上出现极端 `1e-7/0.999999`，优先使用 train-only 分位数门限和 OOF score，不能直接把固定绝对阈值带到官方测试。

### 事件复核层

把同一候选及其前后上下文聚合成一个“候选事件样本”，特征包括：候选窗口的运动统计、候选序列分数、周边候选密度、前后窗口对称性、质量覆盖率、候选开始/结束位置。先用 HistGradientBoosting/LightGBM 类树模型建立强基线，再比较 TCN/Transformer 产生的上下文表示。训练复核器时需要 train participant 内的 OOF 候选分数；直接用同一模型的 in-sample 极端分数会造成复核器失真。最终输出事件置信度，不把每个局部窗口当作独立最终事件。

### 事件化与指标

事件化必须显式记录阈值、最短持续时间、相邻事件融合间隔以及边界修正。评估器实现官方的 `IoU > 0.25` 严格条件和一对一匹配，输出 TP/FP/FN、Precision、Recall、F1、start/end MAE、长 FP 比例和按 participant 的均值/标准差/最差值。

## 3. 训练与验证协议

- 仅按 participant 做冻结拆分；同一 participant 的文件不能同时进入训练和验证。
- 先固定一份开发验证 split，阈值和后处理参数只在训练内部选择；外层 split 只用于最终比较。
- `test` 目录和官方 test 元数据不能进入训练、阈值选择、架构选择或误差分析。
- 每次实验必须保存配置、split manifest、时间轴审计摘要、预测事件表和指标 JSON；禁止只保存一个 F1 数字。
- 任何报告的“高分”必须同时给出覆盖率、长 FP 比例和 participant 分布，避免稀疏打分造成伪高 PPV。

## 4. 外部数据策略

外部数据是可验证的第二阶段变量，不是第一天混入训练集的默认选项。

1. `target_only`：只用竞赛训练数据，作为不可替代的基线。
2. `external_pretrain -> target_finetune`：先在 FD-I/FD-II 等形态相近的 IMU 数据上训练通用候选表示，再只在竞赛训练数据上微调。
3. `joint_train`：只有外部预训练明确改善冻结验证集且不增加长 FP 时才测试。
4. 自监督预训练最后测试，避免在数据契约未稳定时增加不可控变量。

FD-I/FD-II 的采样率、设备和任务相近，优先级高，但其 CC-BY-NC-ND-4.0 许可需要在竞赛提交前确认兼容性；WIMID 数据的权利声明不够明确，未经书面确认不用于最终提交。外部数据的验收条件是：冻结验证集 event F1 提升，同时 participant 最差 F1、不利边界误差和长 FP 比例不恶化，并完整披露数据来源与许可。

## 5. 关键决策与否决条件

- 如果 dense candidate Recall 高但 event F1 仍低，优先调事件复核/解码，不再盲目加深局部 CNN。
- 如果训练集指标上升而 participant-frozen event F1 不升，判为过拟合或泄漏风险。
- 如果加入 PPG 后只有窗口级 AUC 上升、事件级 F1 和长 FP 变差，回退到 IMU 主轴并保留 PPG 仅作质量特征。
- 如果 TCN 产生的候选分数不能在相同候选表上改善事件复核器，TCN 不是当前瓶颈，不继续堆叠复杂度。
- 如果任一实验依赖 GT 邻域稀疏采样、跨缺口插值或 test 信息，实验无效，不能进入排行榜路线。
